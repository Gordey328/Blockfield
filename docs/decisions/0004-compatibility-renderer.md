# 0004 — Browser renderer and extension adaptations

Date: 2026-10-10. Status: implementation decision within the authorized Godot browser port; full parity acceptance remains pending.

Godot Compatibility/WebGL2 replaces the original custom OpenGL renderer. Original voxel colors, AO data, models, textures and effect formulas remain source references. Engine-specific substitutions require numeric, GPU and exported-browser checks; exposing a checkbox is not acceptance.

Current direct lighting/shadows use Godot lights. The native flashlight projector is unavailable in Compatibility; a warm spot plus a 30% local fill reproduce its cone/color/rise behavior. Terrain now samples the original 16×16 tile AO atlas with source face masks/UV mapping. Water uses a source-shaped spectral field, guarded screen-depth refraction and optional mirrored geometry reflection.

The post chain supplies FXAA/MSAA, original lens textures/flares, color correction, camera/hurt blur, depth-of-field and SSAO. The optional float HDR path below supplies source exposure adaptation and pre-tone dust bloom; the ordinary renderer retains LDR bloom/tone controls. An ambient-energy slider is a fill-light choice. A separate optional palette-bounce irradiance cache implements source directional coefficients/13×13 visibility samples with bounded, observer-centered four-meter probes and a per-frame work budget.

The spectral field retains the strongest32 modes at128² rather than running the native full FFT. Reflection shares mesh/MultiMesh resources in its own RenderingServer scenario, clips below-water geometry and excludes first-person/post layers. Budgets cap resolution320×240, refresh20Hz,768 geometry proxies,16 lights and4096 scanned nodes; it defaults off. Reflected shadow atlases, native Water3 depth raymarch, arbitrary extension PBR/skinning and full-map native irradiance volumes remain fidelity gaps. Numeric/GPU evidence and exact limits are in ../voxel.md; exported browser acceptance is recorded separately.

Native AngelScript extensions are replaced by trusted GDScript first/third-person skin factories and validated data-only ZIP resource packs. Uploaded scripts/PCK files are not executed. The runtime pack API validates paths, hashes, types and budgets and refreshes cached resources. Native AngelScript source/API compatibility and uploaded fonts are unsupported. The console provides implemented native cvar aliases without claiming the entire native configuration catalog; see ../extensions.md and ../ui.md.

These documented substitutions do not by themselves mark U14/U15/U18 or iteration 1 complete. Record the actual implemented behavior and evidence in ../parity.md; keep unresolved native features visible there.

## Optional floating-point HDR and source auto exposure

Main/HUD/console expose optional floating-point HDR and native exposure controls, refresh the resolved dust texture after resource-pack changes and move correction/bloom ahead of tone mapping. The ordinary post layer disables its duplicate bloom/correction/tone passes. A reference-camera AudioListener3D preserves positional listening while the cloned camera renders. A real-scene washout exposed an incorrect color boundary; the normalization fix below now passes headless47/0, native exposure32/0, color79/0 and actual-Main63/0. Actual exported WebGL probes pass exposure32/0 and color79/0 with reported renderer `WebKitWebGL` and `float_color_buffer=true`. Camera/hurt blur, lens/flares and FXAA remain later display passes. These are implemented renderer adaptations, not full U15/B03 acceptance or a sustained browser performance result.

The Godot 4.7 renderer overview table describes Compatibility as RGBA8/LDR. The pinned 4.7.2 binary `ed1daf0bf` implements a newer path: `SubViewport.use_hdr_2d` allocates RGBA16F and its GLES3 3D scene buffers inherit that color format. This was checked against [Godot texture storage](https://github.com/godotengine/godot/blob/ed1daf0bf/drivers/gles3/storage/texture_storage.cpp) and [GLES3 scene buffers](https://github.com/godotengine/godot/blob/ed1daf0bf/drivers/gles3/storage/render_scene_buffers_gles3.cpp), then tested through pixel readback. Prefer these pinned source/behavior checks over the older [renderer overview](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html) table. Browser support also requires `EXT_color_buffer_float` on the engine's actual WebGL2 context; absence keeps the ordinary renderer active.

`presentation/hdr_scene_viewport.gd` owns a shared-World3D HDR scene viewport and cloned camera. It synchronizes pose, projection, near/far, viewport dimensions, camera environment and cull mask. Original geometry, first-person equipment and camera children remain in their existing world. While enabled the original viewport's 3D render is disabled and its camera ceases to be current; the clone renders that world once. The HDR present CanvasLayer is −10, before the existing post layer −5 and HUD. Disable/cleanup restores the original viewport/camera state. The option defaults off until the integrated browser performance and post ordering checks pass.

Floating-point storage does not imply linear scene values. The pinned GLES3 `scene.glsl` applies `linear_to_srgb` before writing its 3D target, including the float path. Passing that encoded image directly into native exposure/bloom/gamma raised dark colors and washed out the actual lab. `HdrExposure.setup(texture, compatibility_encoded=false)` therefore makes the boundary explicit: both HdrSceneViewport call sites pass true; already-linear 2D callers keep false. One full-size float pass in `hdr_normalize.gdshader` computes `encoded > 0 ? pow((encoded+.055)/1.055,2.4) : 0` exactly once. Meter, bloom and presentation share this linear texture. Highlights are not clamped to1, intermediate HDR textures are not decoded again, and zero preserves the engine's unrecoverable near-black clamp. This contract is specific to Godot4.7.2 Compatibility; recheck it when changing renderer/engine. Details and before/after visual evidence: [hdr-investigation.md](../hdr-investigation.md).

`presentation/hdr_exposure.gd` keeps metering and temporal gain entirely on the GPU. Native references are OpenSpades v0.1.3 `GLAutoExposureFilter.cpp`, `AutoExposurePreprocess.fs`, `AutoExposure.fs`, `Nonlinearize.fs` and `ColorCorrection.fs`: first bilinear downsampling precedes `max(R,G,B)`; invalid brightness outside 0..16 resets to .05; brightness clamps to .05..1.3 and is raised to the fourth power; the remaining ceil-half pyramid averages that power. Gain is `.6 / fourth_root(mean_power)` bounded by `2^minEV..2^maxEV`, with original defaults −1.5/+0.5. Adaptation blends previous gain at `1 − .01^(dt*speed)` with default speed1. Separate float gain targets avoid a framebuffer feedback loop.

Native gamma `pow(rgb*gain,1/2.2)` precedes optional tint/manual exposure/saturation, then native square → ACES(.8) → square root and enhancement. Those operations occur in `hdr_present.gdshader` before the first RGBA8 output. Its `tint`, `exposure`, `saturation`, `enhancement` and `correction_enabled` uniforms allow integration to move color correction ahead of tone mapping; the LDR post pass must not repeat them or apply a second tone map. A gamma-adjusted image is not itself evidence of HDR.

HDR bloom ports the actual `r_bloom` path, `GLLensDustFilter`/`Gauss1D.fs`/`LensDust.fs`; the separate `GLBloomFilter` is not used by `GLRenderer` here. Each ceil-half level runs the exact four bilinear Gaussian offsets ±2.30654399138844/±.629455560633963 and weights .178704407070903/.321295592929097, horizontally and vertically. Reverse composition uses `count/(count+1)` to average the coarse levels. The native linear final formula is `.95*scene + 2*dust²*blur + grain*.003`, clamped nonnegative. It operates before exposure/gamma/tone, with no LDR brightness threshold. The bloom toggle stops these GPU passes and restores the halo-free image. `set_bloom_dust_texture()` accepts the resolved original/override texture from the resource-pack owner. The default procedural grain retains amplitude and the two native pixel frequencies; it replaces the source per-frame random-byte texture and is not its exact RNG sequence.

Budgets differ from the native renderer. The first meter pass is capped at128×128 by default, preserving aspect ratio; it samples a bounded grid and can miss tiny highlights. `set_meter_budget()` permits16..512 per axis. HDR bloom caps its initial half-resolution pass at256×256 and subsequent hierarchy at six levels instead of native up to ten; `set_bloom_budget()` allows16..512 and1..10 levels. The full-resolution bloom composite is evaluated by the final present shader and first meter pass; the meter reconstructs four bilinear source texels rather than allocating another full-resolution bloom-composite target. Godot's physical SubViewport minimum is2×2, so logical one-pixel rows/columns and final1×1 averages are replicated into2×2 targets at their native sample centers. Stats expose physical/logical meter dimensions, bloom levels/pass count, meter/gain/bloom bytes, scene bytes and normalization size/bytes. Scene and normalization each cost width×height×8 color bytes; normalization adds7,372,800 bytes (7.03MiB) and one fullscreen pass at1280×720. Estimates exclude depth/MSAA and driver overhead. There is no per-frame CPU luminance readback in production.

Current evidence uses the production normalization/filter chain: `test_hdr_exposure.gd` **47/0**, `render_hdr_exposure.gd` **32/0**, `probe_hdr_color_space.gd` **79/0**, and actual-Main `render_hdr_lab.gd` **63/0**. Native GPU tests ran on Intel UHD/OpenGL3.3 Compatibility; Main checks restore preferences byte-for-byte and cover weapon/HUD/depth visibility, bloom, camera restoration, MSAA, resize and disable/re-enable. The color probe compares six actual 3D swatches against already-linear 2D controls and an intentionally incorrect encoded-input control. The corrected Main captures retain green ground, blue forearms, orange skin and a dark rifle; numeric checks alone had missed the previous washout. The updated 3D fixture's authored ALBEDO(1.5,1,.5) reconstructs linear radiance approximately(2.584077,1,.214967); authored albedo, raw encoded readback and linear radiance are different quantities. The implementation retains source exposure/dust-bloom formulas without claiming identical native lighting/color calibration.

Reproduce numeric checks with `godot --headless --path game --script <absolute-path>/tests/presentation/test_hdr_exposure.gd`; use a real graphics context for `render_hdr_exposure.gd`, `probe_hdr_color_space.gd` and `render_hdr_lab.gd`. `python tests/presentation/export_hdr_probe.py --godot <pinned-executable> --probe exposure` builds `.cache/hdr-web-probe/build/index.html`; `--probe color-space` builds `.cache/hdr-web-color-probe/build/index.html`. Both include `hdr_normalize.gdshader`. Serve each directory over HTTP and inspect visible `#hdr-probe-results`/`window.hdrProbeResult`: the coordinator observed actual browser **32/0 exposure** and **79/0 color**, reported renderer `WebKitWebGL`, with `float_color_buffer=true`. Raw texture readback can report FORMAT_RGBAF while returning clipped values; the probes encode known float ranges on GPU and reconstruct from8-bit readback with explicit range/255 tolerance. CPU format metadata alone does not establish GPU range. These exported isolated probes do not validate the published c4 gameplay release, all browser renderers, Title-map quality, input/audio or sustained frame time.

This implements actual HDR storage, correct Compatibility encoding normalization, source auto exposure and pre-tone HDR bloom. Main disables old LDR bloom and repeated color correction/tone mapping while HDR is active. Remaining fidelity differences include bounded pyramid sizes, procedural grain, later lens/camera-effect ordering, Godot lighting/color calibration and native framebuffer/sRGB modes.
