> Historical pre-removal design/evidence. Multiplayer was withdrawn on2026-10-12
> under [ADR0031](decisions/0031-offline-only-game.md). Deleted networking paths

`tests/network/test_runtime_epoch.gd` exercises trusted `BlockfieldServerRuntime.reset_match(new_writable_map, profile="", mode="")` through actual WebSocket sockets and full ClientReplica receivers. Reset immediately sends greater-epoch MATCH_PREPARING17 on the existing game connection; the later compatible WELCOME matches that announced identity. Clients complete a new baseline, ordered changes, map barrier and owner state before play. The separate [long-reset contract](match-preparation.md) proves paused prediction, queued FIFO/deadlines and supported physical water metadata.

The suite prepares three connected owners with sparse IDs and one disconnected grace identity. Two owners pause polling while reset begins, proving that two active transfer jobs retain the bound and the third waits in the queue. A trusted authority edit after their frozen baseline0 must arrive as transaction1 before barrier1; the third queued baseline starts at sequence1. Completing a barrier releases the queued stream. It verifies exact new dimensions/colors/map sequence, stable actor IDs, original team/class preference restoration, source0.75→0.76 inventory, cleared scores/winner/objectives and spectator status. Replacement WELCOME observations check cleared old map, prediction, remote buffers, effect identities and input/chat/request/event cursors. Credentials rotate; old epoch input/request packets on a real preserved socket cannot change the new actor/map or disconnect its current owner.

After disconnect, an old resume token must fail and the same actual Replica is reused with the new rotated token, rebinding the same stable actor. A second reset interrupts that actual resume while its prior map is still loading, then verifies that both live and joining clients install the latest epoch. Disconnected grace credentials cannot resurrect an old identity. Invalid reset inputs (non-increasing epoch, invalid profile/mode, read-only/no-spawn maps) leave the active authority, registry, events, clock and credentials unchanged. Diagnostics retain only capability hashes; no raw resume or bulk capability is printed.

Real sockets exposed two lifecycle races hidden by earlier fake transports. Intentional stops retain terminal events; close/reset drains them before reuse. Independent game/map TCP streams cannot establish cross-stream delivery order by sending a game packet and immediately closing bulk. Runtime revokes bindings/stops senders immediately but retains idle old sockets until the client consumes its early MATCH_PREPARING announcement and closes them. Active240-second transfer deadlines, a separate bounded reset-wait deadline and owner disconnect also clean retired sockets; see match-preparation.md.

The unfinished old bulk HELLO needs the same treatment. Runtime retains at most64 digests for already delivered, unused capabilities until their original15-second deadline; one compatible late HELLO receives only an idle retired socket, without a Registry binding or map data. The real-socket suite explicitly completes this old HELLO while the game stream stays paused, checks that no map packet arrives, and rejects both the same capability's replay and an unknown capability with policy close1008. After new readiness, retired sockets must be gone. No old capability grants access to the replacement map or actor.

Godot4.7.2 native headless result: **722 assertions,0 failures**,274 polls, maximum2 active reset/join jobs; clean stderr. Poll-related assertion counts can vary with socket scheduling. Parser check also passed. This is localhost socket evidence for epoch reset and readiness behavior. It does not establish browser WSS/TLS hosting, renderer/UI reset handling or the dedicated coordinator's ten-second automatic round transition; those are separate integration checks.
