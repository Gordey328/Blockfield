# Connected client model

`BlockfieldClientReplica` is a poll-driven RefCounted, independent of Input, scenes, sound and saved preferences. It owns two transports, private map staging, a live transaction assembler, full-owner ClientPrediction and per-remote interpolation buffers. Renderer installation is supplied through trusted `set_map_callbacks(install,apply_transaction)` callbacks; otherwise pure tests mutate only its private Data. The callbacks must adopt the same Data and apply each transaction exactly once through World, not Data then World.

`connect_to(game_url,map_url,name,spectator=false,resume_token=empty)` starts a new stream. The lifecycle is connecting → joining → loading → synchronizing → live. Matching WELCOME precedes BEGIN; bulk opens only after BEGIN. Only verified baseline/deltas/END data installs, followed by MAP_READY. The first complete MATCH_STATE must match epoch, owner, generation, header/body tick, dimensions and exact installed map_sequence. Post-barrier deltas precede the matching state on the game socket. Unknown server directions, gaps, before-color mismatches and bounded transport/event overflow explicitly fail/close the stream.

`submit_input(buttons,move,yaw,pitch,tool=255,weapon=255)` is called once per client fixed step. It validates and sends a bounded intention record, predicts only that command, and queues its cosmetic records. It never supplies hit/damage/position/resource outcomes. `send_chat` supplies sender_id0. `get_owner_state`, `get_public_state` and remote samples return owned presentation data. Public peers have no HP/ammo/controls/RNG. `resume_token()` returns an in-memory capability copy for explicit reconnect; no token is written to preferences/build info/logs. `close()` stops sockets/staging and clears replica history. There is no automatic endless reconnect loop.

Full snapshots use explicit MATCH_STATE14; Protocol additionally verifies that envelope epoch/tick/generation agrees with its independently validated body. New lives reset prediction, and server runtime ignores already-in-flight older-generation TCP input frames rather than remapping them to a new life. A future-generation or invalid current stream still fails admission.

After a map edit, prediction pauses until the matching complete state arrives. If historical terrain is unavailable, the client stops submitting, waits until all old submitted commands are acknowledged, then explicitly resets prediction at that new confirmed terrain without restarting input sequence. The server lease neutralizes held controls meanwhile. This is a conservative current rebase policy; historical terrain rewind for hits and uninterrupted movement replay across destructive edits are separate requirements. Suspended browser tabs/long stalls still need the rendered adapter's explicit reconnect policy.

Unsent cosmetic/event records are capped512. Remote clock sampling extrapolates the latest received server tick using monotonic local elapsed time and the interpolation module's bounds; full jitter/clock estimation has not been measured. Confirmed game-event routing/deduplication is being integrated separately. The model's pure/native checks do not prove the exported rendered browser/WSS experience.
