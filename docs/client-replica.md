# Connected client model

> Historical pre-removal design/evidence. Multiplayer was withdrawn on2026-10-12
> under [ADR0031](decisions/0031-offline-only-game.md). Deleted networking paths
> and server instructions below do not apply to the current offline game.

`BlockfieldClientReplica` is a poll-driven RefCounted, independent of Input, scenes, sound and saved preferences. It owns two transports, private map staging, a live transaction assembler, full-owner ClientPrediction and per-remote interpolation buffers. Renderer installation is supplied through trusted `set_map_callbacks(install,apply_transaction)` callbacks; otherwise pure tests mutate only its private Data. The callbacks must adopt the same Data and apply each transaction exactly once through World, not Data then World.

Current build/rules compatibility identities are `blockfield-godot-4.7.2-network-3` and `blockfield-source-v0.1.3-authority-3`; their SHA256 hashes must match HELLO/WELCOME. The protocol envelope version remains1. Replica consumes MATCH_STATE14, GAME_EVENTS15 and MATCH_PREPARING17, and sends PLAYER_REQUEST16 alongside input/chat/map families. A greater trusted preparation announcement pauses input and clears old presentation/prediction immediately; the later WELCOME must match that exact announced identity. See [match-preparation.md](match-preparation.md).

`connect_to(game_url,map_url,name,spectator=false,resume_token=empty)` starts a new stream. The lifecycle is connecting → joining → loading → synchronizing → live. Matching WELCOME precedes BEGIN; bulk opens only after BEGIN. Only verified baseline/deltas/END data installs, followed by MAP_READY. The first complete MATCH_STATE must match epoch, owner, generation, header/body tick, dimensions and exact installed map_sequence. Post-barrier deltas precede the matching state on the game socket. Unknown server directions, gaps, before-color mismatches and bounded transport/event overflow explicitly fail/close the stream.

`submit_input(buttons,move,yaw,pitch,tool=255,weapon=255)` is called once per client fixed step. It validates and sends a bounded intention record, predicts only that command, and queues its cosmetic records. It never supplies hit/damage/position/resource outcomes. `send_chat` supplies sender_id0. `request_team(team)` and `request_block_color(color)` send typed PLAYER_REQUEST16 with a contiguous local request sequence; Match decides their outcomes. Class selection remains the weapon input intention. `get_owner_state`, `get_public_state` and remote samples return owned presentation data. Public peers have no HP/ammo/raw controls/RNG, and even the private owner's wire snapshot omits server RNG. `resume_token()` returns an in-memory capability copy for explicit reconnect; no token is written to preferences/build info/logs. `close()` stops sockets/staging and clears replica history. It drains all retained intentional-stop events so the same Replica can immediately connect/resume again. There is no automatic endless reconnect loop.

Full snapshots use explicit MATCH_STATE14; Protocol additionally verifies that envelope epoch/tick/generation agrees with its independently validated body. New lives reset prediction, and server runtime ignores already-in-flight older-generation TCP input frames rather than remapping them to a new life. A future-generation or invalid current stream still fails admission.

After a map edit, prediction pauses until the matching complete state arrives. If historical terrain is unavailable for replay, the client stops submitting, waits until all old submitted commands are acknowledged, then explicitly resets prediction at that new confirmed terrain without restarting input sequence. The server lease neutralizes held controls meanwhile. This is a conservative current rebase policy. Runtime firearm history is implemented separately on authority; it does not provide uninterrupted client movement replay across destructive edits. Suspended browser tabs/long stalls still need browser acceptance of the rendered adapter's explicit reconnect policy.

GAME_EVENTS15 accepts only typed confirmed outcomes for an installed current epoch. Duplicate completed batches are ignored; overlapping cursors fail. Global sequence gaps are valid when owner-private events were routed to another client. Replica rejects a foreign owner-only event even after wire validation. Each outcome is copied and receives `predicted_already_played` from its bounded action identity history, including the source grenade cook/release linkage. Main routes it once to NetworkSession, visuals and audio; replay never produces confirmed damage or duplicate projectiles/feed. Confirmed shot rays are public outcomes, and local recoil still comes from shared prediction once.

Pending cosmetic/confirmed records are capped 512, and predicted-effect suppression retains at most 2048 identities. Remote clock sampling extrapolates the latest received server tick using monotonic local elapsed time and the interpolation module's bounds; remote pose extrapolation is bounded to 100 ms then freezes. Full jitter/clock estimation has not been measured.

## Epoch replacement

Greater-epoch MATCH_PREPARING17 retains the game connection/endpoints/callbacks, stops/drains old bulk and clears map, prediction, remote interpolation, pending effects and command/event cursors. It emits `epoch_reset` plus `match_preparing` and pauses in `preparing`. The matching WELCOME must preserve announced epoch/ID/generation1/profile; it then starts joining and the new map/state barrier. Unannounced, repeated or mismatched replacement packets fail closed. A genuine failure of the new bulk stream remains fatal.

Runtime keeps revoked old bulk sockets idle until the early game-socket announcement makes clients close them, with owner-disconnect/deadline cleanup. An already-started old bulk HELLO may retire once using a compatible unexpired capability, without new bytes/binding. This prevents independent map-socket closes from reaching a loading client before its epoch notification. See [runtime-epoch.md](runtime-epoch.md).
