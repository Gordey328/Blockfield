# Native runtime, connection ownership and input admission

> Historical pre-removal design/evidence. Multiplayer was withdrawn on2026-10-12
> under [ADR0031](decisions/0031-offline-only-game.md). Deleted networking paths
> and server instructions below do not apply to the current offline game.

`BlockfieldServerRuntime` owns two poll-driven transports, `BlockfieldSessionRegistry`, one `BlockfieldInputQueue` per bound actor and the shared `MatchSimulation`. No renderer, settings, Input singleton, HUD, sound or visual grenade node is instantiated. `configure(simulation,build_hash,rules_hash)` is trusted; `start(game_port=0,map_port=0,bind_address="127.0.0.1")` returns actual native ports; `poll()` handles sockets/joins between steps; `step_once()` advances exactly one authority tick; `stop()` releases both listeners.

`game/entry.gd` selects the dedicated scene only for the `dedicated_server` feature or explicit user argument `--server`. Ordinary headless offline tests retain the original lab. The dedicated Node calls `poll` in process and one `step_once` per engine 60 Hz physics callback. Large workload/catch-up behavior is not yet a sustained-performance acceptance result.

## Ownership and join sequence

HELLO must have zero epoch/tick/sequence and compatible32-byte build/rules hashes. Current identities are `blockfield-godot-4.7.2-network-3` and `blockfield-source-v0.1.3-authority-3`, hashed by Compatibility; envelope version remains1. Roles are playing guest0, spectator1, paired bulk2. Only the trusted Match allocator creates actor IDs; a bulk socket never creates an actor. All game and bulk bindings are separate even when numeric IDs coincide. Public registry views contain connection/generation/readiness data; a separate trusted reset helper returns owned unused-capability digests, never client wire credentials.

Resume requires a disconnected actor within30seconds, the same role and a matching32-byte capability digest. Active ownership cannot be taken over. Successful resume rotates both tokens and repeats the map barrier. Disconnect immediately neutralizes controls, drops cooked grenade/intel through Match rules and revokes the bulk socket; the identity/scores remain during grace. Expiry asks Match to remove the actor while retaining already-thrown projectiles.

Baseline preparation uses an immutable packed snapshot and incremental SHA ranges; WELCOME waits until preparation completes. Reset sends capability-free MATCH_PREPARING17 immediately, so existing clients pause before expensive hashing or queued admission. A fresh one-time bulk token with15seconds lifetime is issued at WELCOME, followed by BEGIN on the game socket. The client opens `/map` only after consuming BEGIN. Chunks use bulk; ordered transactions and END use game. END freezes a later map barrier, while newer transactions remain queued until matching READY. A live client receives post-barrier deltas before its latest state. Initial guest spawn follows map readiness. The supported native network map has physical water1/wade2; configure/reset reject custom or nonfinite levels atomically.

At most two join preparations/transfers are active concurrently. Additional connected owners during reset wait queued and do not freeze a map until admitted to that budget. Each peer retains at most128 transactions,32768 changes and8MiB of estimated encoded deltas. A240second absolute join deadline includes preparation and validation. Slow peers, gaps and over-budget edits close their current stream explicitly; reconnect requests a fresh baseline. Transport heartbeat/backpressure remains separately bounded. Old map streams are invalidated before the trusted `acknowledge_map_resync()` clears Match's sticky overflow marker.

## Command family semantics

INPUT_BATCH header epoch is the match epoch, sequence is the actor's **spawn generation**, and tick equals the final record's input tick. Each batch has1..8 contiguous records, each generation starts with sequence1 (or the trusted acknowledged sequence+1 after reconnect). Across batches sequence must remain contiguous and input ticks strictly advance. Admission accepts ticks no more than15 behind or8 ahead of current server time; this is a queue window, not a rewind permission.

The queue owns decoded Command copies, with at most32 pending. Each server step consumes at most one eligible command. Future commands wait; clients cannot request dt or multiple simulation steps. An expired backlog requires resync rather than hidden skips. Six ticks without a consumed command clear held controls and the admitted shot-tick lease; clearing retains cooking and previous button edges until the next rules step, so release follows the normal authority path. Epoch/generation transitions clear old commands and acknowledgment state. Delayed older-generation input/request frames are ignored; malformed current or future-generation frames cannot authorize a new life.

CHAT intents have sender_id0 and contiguous per-session message IDs. Runtime assigns the actual sender and global ID, enforces four messages per five seconds and routes team chat only to the same team. Chat generation/epoch must match. Only ready clients receive chat; backpressure closes the affected stream.

PLAYER_REQUEST16 carries only `{action,value,request_sequence}`: action0 requests team0..2, action1 requests canonical packed block color `0x01RRGGBB`. Runtime binds requests to the ready authenticated owner/current epoch/generation, requires contiguous request sequence and the admitted tick window, and limits requests to 16 per five seconds. A spectator admission cannot request a playing team. Match decides team/life and palette outcomes. Weapon class remains an input intention, preserving source pending-class and respawn behavior; a request cannot supply stock, HP or damage.

GAME_EVENTS15 serializes committed journal outcomes through EventsCodec. Public events go to ready peers; `hurt,hit_confirmed,class_pending,dry_fire,build_error,blocks_used,block_recovered,restock` go only to their event owner. Private routing can create legitimate gaps in the global event sequence. Each peer retains at most 16 event frames and 256 KiB; overflow closes that peer rather than silently dropping effects. Ordered map deltas precede confirmed event frames, which precede the latest unsent state. Client-origin GAME_EVENTS is an invalid direction.

## Firearm history and respawn policy

After each fixed step, Runtime records completed actor poses plus the step's committed terrain receipts in HitHistory. Admitted input ticks are retained per authenticated actor and clamped to the latest closed simulation tick before firearm queries. Match queries exact same-time actor hit volumes and terrain, plans all shots before damage/edits and checks current victim generation/eligibility and block color before committing. History retains latest plus 15 prior ticks; missing/out-of-window history denies shot damage while source ammo/cadence and confirmed shot/tracer still occur. Melee, grenades, building and objectives retain current-time authority. See [match-rewind.md](match-rewind.md) for authored policy and cost limits.

Ready/live, connected playing actors automatically respawn at or after their 180-tick death deadline. Loading, disconnected and spectator actors cannot use this authored policy. Spawn changes generation, resets input/request/shot-tick admission and uses source inventory/class rules. Old-life in-flight input cannot damage or control the new life.

## Trusted epoch replacement

`reset_match(new_writable_map,profile="",mode="")` validates a greater epoch, map, profile and mode before replacing active state. A new Match restores connected sparse actor IDs, names, role and team/class preferences; old scores, inventory, objectives, grenades, event/input/chat/request streams and hit history are discarded. Empty profile/mode preserve their current values. Disconnected grace identities are invalidated. Registry prepares all replacement credentials/WELCOMEs atomically and keeps the existing game connection. Owners remain inactive until their new baseline/barrier; playing owners then spawn with fresh source resources, while spectators stay inactive.

Reset queues connected owners through the same two-job bound. Old senders stop and registry bulk bindings/capabilities revoke immediately. Runtime retains old idle bulk sockets until clients process the early greater-epoch announcement and close them, their owner disconnects or a bounded deadline expires. Waiting owners have a separate capacity-derived64-minute hard cap; active transfers retain240seconds from actual admission. Fresh/resume admissions cannot overtake waiting reset owners. At most64 digests for delivered unused bulk capabilities remain until their original15-second deadline: one compatible late HELLO can create an idle retired socket only, without binding/map bytes. Unknown, replayed and expired capabilities reject. Older input/request/READY/chat in TCP cannot mutate the new match. See [runtime-epoch.md](runtime-epoch.md) and [match-preparation.md](match-preparation.md).

## Current snapshot boundary and verification

Private owner readiness/controls/cadence/resources are addressed only to that owner's game connection. Server shot RNG is never encoded. Public remote actors omit HP, inventory and raw controls; their alive flag is authoritative. `set_snapshot_factory(Callable)` remains a trusted test/extension hook. Legacy SNAPSHOT13 remains supported by Protocol for its existing fixtures; production uses MATCH_STATE14 and the GAME_EVENTS15 feed.

Unsent state is replaceable at20Hz; bytes already queued into ordered TCP are not withdrawable. Deltas retain order and are never silently replaced. Fixed-step publication and transport polling are distinct operations.
